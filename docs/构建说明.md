# stamky v0.9.3 构建说明

## 1. 正式目标

- C++20 / Win32；
- x86（CMake `-A Win32`）；
- x64（CMake `-A x64`）；
- 官方支持/测试目标 Windows 10+；
- 推荐 Visual Studio 18 2026 + MSVC + Windows SDK。

`cmake_minimum_required` 仍为 3.25，因为项目语法和 VS17 2022 fallback 不要求更高版本；但 **Visual Studio 18 2026 generator 是 CMake 4.2 才新增的**，所以凡是使用 `-G "Visual Studio 18 2026"` 的正式 VS2026 构建都要求 CMake 4.2+。

## 2. 一键脚本

```text
构建_x86_Release.bat
构建_x64_Release.bat
构建_全部_Release.bat
```

单架构脚本优先寻找 Visual Studio 18 2026 自带 CMake；找不到时使用 PATH 中的 `cmake`。配置优先 `Visual Studio 18 2026`，失败后再尝试 `Visual Studio 17 2022`。

输出：

```text
release\x86\stamky.exe
release\x64\stamky.exe
```

脚本每次先清理对应 build/output，避免失败后把旧 EXE 冒充本次构建结果。

## 3. 手工构建

x86：

```bat
cmake -S . -B build\x86 -G "Visual Studio 18 2026" -A Win32
cmake --build build\x86 --config Release --parallel
```

x64：

```bat
cmake -S . -B build\x64 -G "Visual Studio 18 2026" -A x64
cmake --build build\x64 --config Release --parallel
```

## 4. MSVC 参数

CMake 为 MSVC 设置：

```text
/W4 /permissive- /EHsc /utf-8 /O2 /Gw /Gy
/OPT:REF /OPT:ICF /MANIFEST:NO
```

`/MANIFEST:NO` 是有意设置：`src\stamky.rc` 已作为 `RT_MANIFEST #1` 嵌入自定义 manifest，防止 linker 再生成第二份 manifest 导致历史上出现过的 `CVT1100` 重复资源错误。

## 5. Manifest / 架构

v0.9.3 的 `app.manifest` 使用：

```xml
processorArchitecture="*"
```

因此同一资源脚本可用于 x86/x64，不再把 x86 EXE 错标为 amd64。

manifest 同时声明 Common Controls v6、asInvoker、PerMonitorV2、longPathAware。

## 6. GitHub Actions

`.github/workflows/build.yml`：

- runner：`windows-2025-vs2026`；
- matrix：Win32 / x64；
- generator：Visual Studio 18 2026；
- Configure 前先检查当前 `cmake` 是否真的提供 VS18 2026 generator，不满足 CMake 4.2+ 能力时直接失败；
- 每个架构单独 artifact；
- artifact 内含 `stamky.exe`、SHA-256、README、版本/项目文档；
- 未找到真实新产出的 `stamky.exe` 时 job 直接失败。

工作流只产出构建 artifact，不自动发布 GitHub Release；正式 tag/Release 流程见 `GitHub发行步骤.md`，以便在 CI Compile/Link 与 Windows 实机回归之间保留明确人工验收边界。

## 7. 编码

- C++：UTF-8，MSVC `/utf-8`；
- Win32 可见文本：宽字符 API；
- RC：`#pragma code_page(65001)`；
- Version Info Translation：简体中文 `0x0804 / 1200`；
- 本地 BAT：GBK + CRLF，对应 `chcp 936`。

## 8. Windows 7 / 8.1 非官方兼容

当前 CMake 定义 `_WIN32_WINNT=0x0A00`，官方构建与测试只覆盖 Windows 10+。

这不表示 stamky 的全部业务逻辑硬依赖 Windows 10。有能力的维护者可以自行：

1. 调整 `_WIN32_WINNT/_WIN32_IE`；
2. 识别并动态解析/回退旧系统没有的 Win32 API；
3. 修改 manifest；
4. 选择仍能生成目标系统可运行二进制的 Windows SDK/MSVC/MinGW 工具链；
5. 重新验证 Common Controls、DPI、Shell/COM、AppUserModelID、任务栏行为。

该路径不属于官方支持，不应在没有实测证据时标注为“兼容 Windows 7/8.1”。

## 9. 当前包的构建状态

当前打包环境没有 Windows SDK/MSVC，因此 **v0.9.3 尚未在此处 Compile/Link**。源码/静态审核 PASS 不能替代实际 Windows 构建。请以 GitHub Actions 或 Windows 本机构建日志作为最终证据。
