# stamky v0.9.3 使用说明

## 1. 启动与退出

直接运行 `stamky.exe`。程序建立单实例后台 Host 并进入托盘。关闭“内容管理”或“设置”窗口不会退出 Host；真正退出请使用托盘菜单“退出”。

如果已有 stamky Host，第二次运行只把命令转发给现有实例，不会建立第二套常驻模型/缓存。

## 2. 内容管理

托盘双击或托盘菜单进入内容管理。UI-06 维持双列表结构：左侧分组，右侧当前组项目。

可以：

- 新建、重命名、删除分组；
- 添加程序、`.lnk`、普通文件、文件夹、URL；
- 新建带参数/工作目录/自定义图标的项目；
- 添加已有分组作为子组；
- 扫描一个文件夹中的可启动文件；
- 多选删除；
- 鼠标拖动或 `Alt+↑ / Alt+↓` 排序；
- 右键刷新图标、打开所在位置/链接、Windows 属性。

右侧 ListView 的当前顺序就是永久菜单顺序，不存在另一个后台排序规则。

### Explorer 拖放规则

- 单独拖入 **1 个普通文件**：始终加入当前高亮组；即使鼠标落在左侧分组列表，也不会因此新建组。
- 单独拖入 **1 个文件夹到左侧分组列表**：新建一个以文件夹名命名的组；组内容同时包含该目录**第一层**中符合当前“可启动文件格式”设置的文件，以及该目录**第一层子文件夹**。子文件夹以 Folder 项目保留，不递归把其内部文件摊平进当前组。
- **多选文件/多对象拖到左侧分组列表**：新建一个组，拖入对象本身作为该组内容；若所有对象来自同一父目录，默认使用父目录名作为组名，否则使用“新分组”。
- 将文件、文件夹或多选对象拖到 **右侧项目列表**：统一作为当前高亮组的子内容添加；因此文件夹拖到右侧时仍是一个 Folder 项目，不会自动变成新组。

拖放不会因为鼠标落在左侧某一行就临时切换目标组；“当前高亮组”始终以已有选择为准。
单文件夹/多对象如果落在按钮区、状态栏等非列表区域则忽略，避免程序猜测用户到底想“建组”还是“加子内容”。

### 添加现有分组为子组

点击“＋ 添加...”后，“添加现有分组为子组”是标准 Win32 **级联子菜单**：鼠标悬停在该项上即可展开候选分组，键盘也可用右方向键进入；只有点击具体目标分组后才执行添加，不再先点击父项再弹第二个菜单。当前组自身以及会形成循环引用的分组不会作为可选目标。

### 子组名称

子组项目的名称来自目标分组。不能单独 F2 把子组改成另一名字；需要修改显示名时，请在左侧重命名目标分组。

## 3. 扫描文件夹

扫描只发生在管理阶段。成功完整枚举后才导入结果；如果目录枚举中途失败/中断，本版会报告失败并且 **不导入部分结果**。

已有项目保持原顺序，新发现项目追加。可启动扩展名可在设置中编辑。

## 4. 创建任务栏组入口

选中分组 → “创建组快捷方式”。输出位于：

```text
GroupShortCuts\<分组名>.lnk
```

每个组拥有独立 `stamky.Group.<GUID>` AppUserModelID。先双击 `.lnk` 确认能弹出正确组，再固定到任务栏。

从旧开发名版本升级时，stamky 会尝试迁移这个目录里仍指向 `StackyModern.exe` / `stackymorden.exe` 的旧组快捷方式。已经固定在任务栏或复制到其他目录的 Shell 副本无法可靠自动修改，请删除旧固定项后重新生成/固定。

## 5. Runtime 菜单

- 左键项目：启动。
- 右键程序、快捷方式、普通文件、文件夹：尝试显示 Windows Shell 原生上下文菜单。
- 子组在用户展开时 lazy build。
- 文件夹只在用户展开时实时枚举，最多取受控数量的可启动项；根菜单热路径不扫描目录。
- 多列顺序为“从上到下，填满后向右”。
- 任务栏入口使用 TaskbarAware 锚定；内容管理里的“预览”按鼠标位置显示。

本版仍没有 Runtime 搜索弹窗，也没有内容管理搜索框。

## 6. 设置

当前设置包含：

- 菜单文字大小：8–20 pt；
- 菜单图标逻辑大小：16–64 DIP；
- 可启动文件格式列表；
- 界面语言；
- 多列之间是否显示分隔线。

设置窗口先编辑副本，只有“保存”成功写入 `settings.ini` 才提交；“取消”不会把格式编辑器中的临时修改泄漏到当前运行态。

### 格式编辑器

- `+` 或输入框内 Enter：添加规范化后的扩展名；
- `-` / Delete：删除选中项；
- 列表上的 Enter 不会误触删除；
- 仅允许受控字符/长度/数量；
- 最终保存与启动加载使用同一规范化规则。

## 7. 数据与恢复

```text
data\groups.tsv      用户内容权威数据
 data\settings.ini   设置
 data\lang\*.ini    语言文件
 data\启动诊断.log   诊断日志
cache\runtime.bin    派生运行缓存
cache\icons\...      派生图标缓存
```

如果 `groups.tsv` 损坏、非法 UTF-8 或结构不完整，程序会停止启动并保留原文件，不会把它当空配置覆盖。

`runtime.bin`/图标缓存损坏时可以重建。v0.9.3 使用 `STAMKY5 / version 5`，旧 cache 自动失效。

## 8. 多语言

语言文件位于 `data\lang\<code>.ini`，`[UI]` 中以中文原文为 key。缺少某个翻译时回退中文，不影响程序运行。默认 `cn.ini/en.ini` 只在不存在时创建，不覆盖用户自定义文件。

升级后如果自定义/旧语言文件缺少 v0.9.3 新增 key，会看到中文回退；可对照新默认文件补译。

## 9. Windows 版本

官方支持/测试目标：Windows 10+。

高级用户可以自行修改目标宏、manifest、较新 API fallback 与工具链尝试 Windows 7/8.1；这是非官方兼容实验，不在本项目测试范围。
