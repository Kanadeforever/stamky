# stamky v0.9.3 性能设计说明

## 目标

- 空闲托盘 Host 保持小型原生 Win32 常驻；
- Runtime 点击时优先从 memory-mapped cache 读取；
- 菜单热路径不扫描源目录、不重新解析全部 `.lnk`、不访问全部目标 EXE 抽图标；
- Manager/Settings/ItemEditor 按需创建，关闭后释放 GUI/GDI 资源；
- 不使用 Electron、WebView、.NET/WPF、Qt 等额外重型 UI runtime。

历史预算仍作为回归参考：空闲 Private Commit 目标约 ≤10–15 MB，普通 Runtime 尽量 ≤20 MB。v0.9.3 尚需 Windows 实机重新测量，不能把历史数字当成本版已通过数据。

## Runtime cache

v0.9.3 使用 `STAMKY5 / version 5`：

- 构建阶段从 Model + 图标派生；
- 写 `runtime.bin.tmp`，完整成功后原子替换；
- 读取使用 CreateFileMapping/MapViewOfFile；
- 严格验证文件总长、组/项目数、字符串、类型、图标 payload、组边界、重复 ID 与精确 EOF；
- RuntimeIconView 像素指针直接指向映射，因此活动菜单存在时禁止替换映射。

旧缓存只作为派生数据处理：magic/version 不匹配就重建，不做复杂二进制就地升级。

## 图标

管理/缓存阶段提取多档预乘 BGRA 图标。Runtime 根据实际 DPI/设置选择接近尺寸，生成 owner-draw HBITMAP。HBITMAP 小缓存受数量限制，不把整个库永久展开为 GDI 对象。

文件夹子项的 HICON 只在用户实际展开文件夹时生成，所有权转移到 DrawEntry；未转移的临时图标在失败路径立即销毁。

## 菜单重入

`TrackPopupMenuEx` 会运行嵌套消息循环，因此“菜单显示中”并不是普通同步临界区。v0.9.3 将重复 SHOW 变成 pending 请求并 `EndMenu`，等活动菜单真正退出后再清理/重建。

这是性能与正确性的共同约束：不能为了立即重建缓存而中途释放当前菜单引用的数据。

## 文件夹展开

根菜单不枚举磁盘目录。只有用户展开 Folder item 时才读取该目录，并限制实时项数；因此一个未打开的巨大目录不会影响每次任务栏弹出延迟。

## 待测性能回归

Windows 实机应至少记录：

- 空闲 Host Private Commit / Working Set / USER / GDI；
- Manager 打开、加载大量项目、关闭后的回落；
- 100 次 Runtime 打开/取消；
- 100 次 Shell 右键打开/取消；
- mixed-DPI 来回移动 Manager/Settings；
- 大分组多列菜单 prepare ms。
